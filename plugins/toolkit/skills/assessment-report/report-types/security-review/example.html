Scope & approach. This review is threat-centric: findings are framed as attacker capabilities, ranked by Likelihood × Impact, and ordered by attacker reach — what an unauthenticated attacker touches first, then lateral movement, then blast radius. Posture is scored across five security domains — Identity & Access, Network & Perimeter, Data Protection & Secrets, Application Security (OWASP Top 10), and Detection & Response — each graded 0–100 across five weighted control dimensions. Every finding carries a confidence flag, a residual score after the proposed control, and an honest deferral stance. Standards are mapped to OWASP Top 10 · CIS AWS Benchmark · NIST CSF in the appendix. This contents list and all section headers are clickable; the PDF carries bookmarks and page numbers.

Executive Summary

Northwind Retail's storefront and API run today behind a WAF, on a private, encrypted database — but the review found 26 findings across five domains, three critical, concentrated in internet-reachable exposures and application code: a public S3 bucket holds a database backup, a shipped dependency carries a remote-code-execution advisory, and the orders API leaks other customers' records — and with no centralized logging or alerting, an intrusion would go unseen. The good news for budget-holders: the highest-risk items are cheap, reversible config or one-line dependency fixes, and hardening adds under $150/mo. The theme is not "sophisticated attacker required" — it is "the front door is unlocked and no one is watching."

Threat Model & Attack Surface

Northwind's estate is a classic public-SaaS shape: an internet edge (CloudFront + ALB + WAF) fronts a stateless application/API tier on ECS, which reads an identity plane (IAM roles & keys) and a data plane (RDS, S3, ElastiCache). The review models the attacker's path across three trust boundaries — edge, application/identity, data — and places each finding where it sits. The alarming part is how short the path from an unauthenticated request to customer data actually is.

No centralized logging or alerting spans any boundary (DR-01/DR-03) — an attacker crossing all three would not trip an alarm. The dashed arc is the shortest unauthenticated path: a public bucket exposes a backup dump directly, bypassing the app entirely.
One hop to data

The public nw-assets-public bucket exposes a database backup with no authentication — the attacker never has to defeat the app, WAF, or login at all.

Flat blast radius

The CI deploy role is *:* and the VPC is unsegmented, so a foothold in the app tier reaches the whole account and every data store.

Blind to intrusion

No SIEM, no security alerts, 7-day logs. An attacker could cross all three boundaries and dwell for weeks before anyone noticed.

The shortest path to Northwind's customer data doesn't go through the login page — it goes through a public bucket and an unpatched dependency, and nothing is watching the door.

Perimeter reads better than it is. The WAF and private RDS earn this domain a "C" — but the WAF's missing rate rule leaves the login open to credential stuffing, and the open bastion plus unrestricted egress mean the edge is hard to enter through the front but easy to leave through the back. Closing SSH (move to SSM Session Manager) and adding an egress allow-list are both sub-quarter-day.
A WAF you don't rate-limit is a lock with the door propped open — it inspects requests it never slows down.

Detection is the multiplier. Every other domain's risk is amplified by this one: a public-bucket download, a brute-forced bastion, or an RCE would all happen silently today. You cannot respond to what you cannot see. Northwind's biggest gap isn't a single hole — it's that no alarm would ring if someone climbed through one.
